# SIMS Mobile API — v1

JSON API used by the SIMS mobile app (React Native / Expo). It runs inside the
same Laravel app and database as the website.

- **Who can use it:** only **active Students (role 1)** and **active Supervisors (role 3)**.
  Coordinators (2) and Administrators (4) are told to use the website.
- **Status:** Module 1 (auth foundation). New endpoints are added per module; existing
  fields are never renamed or removed within `v1` — only new fields/endpoints are added.

## Basics

| | |
|---|---|
| Base URL | `https://<your-domain>/api/v1` (local: `http://127.0.0.1:8000/api/v1`) |
| Request body | JSON (`Content-Type: application/json`). File uploads (later modules) use `multipart/form-data`. |
| Response body | Always JSON (`Content-Type: application/json`), except `204 No Content`. The API never returns HTML or redirects. |
| Recommended headers | `Accept: application/json` on every request |
| Auth | `Authorization: Bearer <token>` on every endpoint except `POST /login` |
| Dates/times | App timezone is `Asia/Manila` (fields added in later modules will state their format) |

### Tokens

- A token is returned by `POST /login`. It looks like `12|Xb4Q...` (an id, a `|`, then 40 random characters). Treat it as opaque; store it in `expo-secure-store`.
- Tokens **do not expire by time**. They stop working when:
  - the app calls `POST /logout` (revokes only that device's token), or
  - an admin or coordinator deactivates the account or changes its role on the website — all of that user's tokens are deleted at that moment, so the next request gets `401`, or
  - the account is otherwise found inactive, or no longer a Student/Supervisor, when a request arrives — that request gets `403` with a `code` (see below) and the token is deleted on the server.
- One token per device login; logging in on a second device does not sign out the first.

## Error format

Every error is JSON with at least a `message`:

```json
{ "message": "Human readable text." }
```

| Status | When | Body |
|---|---|---|
| `401` | Missing, invalid, or revoked token | `{"message": "Unauthenticated."}` |
| `403` | Not allowed. From the auth layer it carries a `code` (below); from a role check on a specific endpoint it is just `{message}` | `{"message": "...", "code": "..."}` or `{"message": "..."}` |
| `404` | Unknown URL or a record that doesn't exist / isn't yours to see | `{"message": "Not found."}` |
| `405` | Wrong HTTP method for the URL | `{"message": "Method not allowed."}` |
| `422` | Validation failed | `{"message": "...", "errors": {"field": ["msg", ...]}}` |
| `429` | Rate limited. `Retry-After` header = seconds to wait | `{"message": "Too Many Attempts."}` |
| `500` | Server error | `{"message": "Server Error"}` |

`422` `errors` keys are the request field names. `message` is the first error (plus "(and N more errors)" when there are several) — show `errors[field][0]` next to each field.

### 403 `code` values

| `code` | `message` | App should |
|---|---|---|
| `role_not_allowed` | `The mobile app is for students and supervisors only. Please use the website.` | Clear the stored token, show the message on the login screen |
| `account_inactive` | `This account has been deactivated. Please contact an administrator.` | Clear the stored token, show the message on the login screen |

When either comes back from an **authenticated** endpoint the server has already deleted the token, so the app must treat it like a logout. Treat any `401` the same way.

### Rate limits

| Endpoint(s) | Limit | Key |
|---|---|---|
| `POST /login` | 5 requests / minute (all attempts, successful or not) | email (case-insensitive) + IP |
| All authenticated endpoints | 120 requests / minute | user |

Responses under a limit include `X-RateLimit-Limit` and `X-RateLimit-Remaining`; a `429` adds `Retry-After`.

## Shared objects

### User

```json
{
  "id": 42,
  "name": "Juan Dela Cruz",
  "email": "juan@example.com",
  "role_id": 1,
  "role": "Student"
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | int | |
| `name` | string | |
| `email` | string | |
| `role_id` | int | `1` Student, `3` Supervisor (the only values the app will ever see) |
| `role` | string | `"Student"` or `"Supervisor"` |

### StudentProfile

```json
{
  "id": 7,
  "student_number": "2026-00001",
  "course": "BSIT",
  "section": "A",
  "internship_status": "ongoing",
  "required_hours": 486,
  "company": { "id": 3, "name": "Acme Corp" },
  "supervisor": { "id": 15, "name": "Maria Santos" }
}
```

| Field | Type | Notes |
|---|---|---|
| `id` | int | Student record id (not the user id) |
| `student_number` | string | |
| `course` | string | |
| `section` | string | |
| `internship_status` | string | `not_started` \| `ongoing` \| `completed` |
| `required_hours` | int \| null | `null` = not set yet |
| `company` | `{id: int, name: string}` \| null | `null` = not assigned to a company yet |
| `supervisor` | `{id: int, name: string}` \| null | `null` = no supervisor assigned yet |

## Endpoints

### `POST /login`

No auth. Exchanges credentials for a token.

Request:

```json
{
  "email": "juan@example.com",
  "password": "secret",
  "device_name": "Juan's Galaxy A54"
}
```

| Field | Rules |
|---|---|
| `email` | required, valid email, max 255 |
| `password` | required, string |
| `device_name` | required, string, max 255 — shown to the user later as the device list; use e.g. `Device.modelName` |

**200 OK**

```json
{
  "token": "12|Xb4QkPz8mN2...",
  "user": {
    "id": 42,
    "name": "Juan Dela Cruz",
    "email": "juan@example.com",
    "role_id": 1,
    "role": "Student"
  }
}
```

**422** wrong email *or* wrong password (identical response either way — it never reveals whether the email exists):

```json
{
  "message": "These credentials do not match our records.",
  "errors": { "email": ["These credentials do not match our records."] }
}
```

**422** missing/invalid fields:

```json
{
  "message": "The email field is required. (and 2 more errors)",
  "errors": {
    "email": ["The email field is required."],
    "password": ["The password field is required."],
    "device_name": ["The device name field is required."]
  }
}
```

**403** correct password but Coordinator/Administrator account:

```json
{
  "message": "The mobile app is for students and supervisors only. Please use the website.",
  "code": "role_not_allowed"
}
```

**403** correct password but deactivated account:

```json
{
  "message": "This account has been deactivated. Please contact an administrator.",
  "code": "account_inactive"
}
```

**429** more than 5 attempts in a minute for this email from this IP:

```json
{ "message": "Too Many Attempts." }
```

### `POST /logout`

Auth required. Revokes **only the token used for this request**; other devices stay signed in.

**204 No Content** (empty body).

**401** if the token is already invalid — the app should still clear its stored token.

### `GET /me`

Auth required. The signed-in user plus a role-specific summary. Exactly one of `student` / `supervisor` is relevant to the role; the other is always `null`.

**200 OK — Student**

```json
{
  "user": {
    "id": 42,
    "name": "Juan Dela Cruz",
    "email": "juan@example.com",
    "role_id": 1,
    "role": "Student"
  },
  "student": {
    "id": 7,
    "student_number": "2026-00001",
    "course": "BSIT",
    "section": "A",
    "internship_status": "ongoing",
    "required_hours": 486,
    "company": { "id": 3, "name": "Acme Corp" },
    "supervisor": { "id": 15, "name": "Maria Santos" }
  },
  "supervisor": null
}
```

A Student account may (rarely) have no student profile yet; then `"student": null`. The app should show a "profile not set up — contact your coordinator" state instead of crashing.

**200 OK — Supervisor**

```json
{
  "user": {
    "id": 15,
    "name": "Maria Santos",
    "email": "maria@example.com",
    "role_id": 3,
    "role": "Supervisor"
  },
  "student": null,
  "supervisor": { "students_count": 12 }
}
```

`students_count` = students whose assigned supervisor is this user.

**401** / **403** (`code`) as described above.

## curl quick start

```bash
# Log in
curl -s -X POST http://127.0.0.1:8000/api/v1/login \
  -H "Accept: application/json" -H "Content-Type: application/json" \
  -d '{"email":"juan@example.com","password":"secret","device_name":"curl"}'

# Use the token
curl -s http://127.0.0.1:8000/api/v1/me \
  -H "Accept: application/json" -H "Authorization: Bearer 12|Xb4QkPz8mN2..."

# Log out
curl -s -X POST http://127.0.0.1:8000/api/v1/logout \
  -H "Accept: application/json" -H "Authorization: Bearer 12|Xb4QkPz8mN2..."
```
